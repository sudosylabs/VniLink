libde265 is linked into the native module. Its exact library source and the
corresponding application source needed to rebuild that module are included
in relink/source. You may modify/relink libde265 and reverse engineer this
combined module for debugging those modifications. Other third-party notices
and terms continue to apply to their respective components.

To replace the decoder:
1. Modify relink/source/vendor/hevc/libde265-1.1.3.
2. From relink/source, run:
   cargo build --locked --target-dir target/relink -p vnilink-node
3. Close VniLink and replace native/vnilink.node with the resulting library:
   macOS: target/relink/debug/libvnilink_node.dylib
   Linux: target/relink/debug/libvnilink_node.so
   Windows: build with --target x86_64-pc-windows-gnu and use
            target/relink/x86_64-pc-windows-gnu/debug/vnilink_node.dll
   Keep the destination filename vnilink.node.
   In an assembled macOS app, the module is at
   VniLink.app/Contents/Resources/app.asar.unpacked/native/vnilink.node.
   On Windows/Linux it is at resources/app.asar.unpacked/native/vnilink.node.
   The relink/source tree is beside app.asar in the same Resources/resources
   directory. The source-checkout layout uses native/vnilink.node instead.

Build prerequisites: the Rust version in rust-toolchain.toml, C/C++ compilers,
CMake and libclang. Windows builds use Rust x86_64-pc-windows-gnu and the
MSYS2 MINGW64 gcc/clang/nasm/make tools. Linux also needs nasm and the desktop development packages
listed in .github/workflows/ci.yml. Cargo fetches pinned registry dependencies;
codec build scripts fetch pinned upstream codec source tags; prebuilt binaries
are checksum verified. Native HEVC uses the bundled source tree.
For a locally modified macOS application, use an ad-hoc signature or launch
Electron against the rebuilt source checkout. Platform signing must not prevent
installation/use of your rebuilt native module.
